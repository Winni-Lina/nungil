1. 담당 기능
----------------------------------------------------------------------
사용자 질문과 AI 답변을 Oracle DB(CHAT_HISTORY)에 저장하고,
일정 번호별로 다시 조회하는 서버 REST API.


2. 현재 문제 (개선 전)
----------------------------------------------------------------------
- 사용자 질문/AI 답변이 UserChatActivity.kt의 conversationHistory(앱 메모리)에만
  임시 저장됨 → 앱을 종료하면 대화가 사라진다.
- 보호자가 사용자의 실제 질문 내용을 다시 확인할 수 없다.


3. 이 기능이 필요한 이유
----------------------------------------------------------------------
대화가 DB에 남아야 다음 기능들의 토대가 된다.
- 앱 재실행 후 과거 대화 복원
- 보호자가 사용자 질문·AI 답변 확인
- 현재 일정의 최근 대화를 Gemini가 참고
- 질문이 반복된 단계 분석
(위 연결 작업은 저장/조회 API가 안정화된 다음 주에 진행)


4. 개선한 내용
----------------------------------------------------------------------
(1) CHAT_HISTORY 테이블 신설 (Oracle)
    컬럼: message_id(PK,IDENTITY), guardian_id, user_idx, schedule_id,
          step_index, chat_mode, sender, message, intent, created_at
    인덱스: (guardian_id, user_idx, schedule_id, created_at)

(2) 저장 API   POST /api/v1/chat-history
    - body: guardianId, userIdx, scheduleId, stepIndex, chatMode, sender, message, intent
    - 입력값 검증(거부 규칙):
        chatMode ∉ {GENERAL, SCHEDULE}      → 거부
        sender   ∉ {USER, ASSISTANT, SYSTEM} → 거부
        message 가 비어있거나 공백만          → 거부
        chatMode=SCHEDULE 인데 scheduleId 없음 → 거부
    - 정상: {"status":"SUCCESS"}
    - 거부: {"status":"ERROR","errorCode":"INVALID_REQUEST","message":사유}

(3) 조회 API   GET /api/v1/chat-history?guardianId=&userIdx=&scheduleId=&chatMode=
    - 조건: guardian_id + user_idx + schedule_id + chat_mode 일치
      (scheduleId 없으면 schedule_id IS NULL = GENERAL 대화)
    - 정렬: created_at 오름차순 (오래된→최근)
    - 결과: {"status":"SUCCESS","messages":[{messageId,sender,message,intent,createdAt}, ...]}
    - 대화 없으면: {"status":"SUCCESS","messages":[]}

6. 입력부터 결과까지 동작 순서
----------------------------------------------------------------------
저장: 앱/클라 → POST /chat-history(JSON)
      → Controller가 body 파싱 → Service.validate(허용값·필수값 검사)
      → 통과 시 Mapper.insert → CHAT_HISTORY 1행 저장 → {status:SUCCESS}
      → 검증 실패 시 저장 안 하고 {status:ERROR, 사유}

조회: 앱/클라 → GET /chat-history(쿼리)
      → Controller → Service.findMessages
      → Mapper.findMessages (조건 4개 일치, created_at ASC)
      → messages 목록 반환 (없으면 빈 배열)


7. 정상 테스트 결과 (PASS)
----------------------------------------------------------------------
- USER 메시지 저장 → SUCCESS
- ASSISTANT 메시지 저장 → SUCCESS
- GENERAL 저장(schedule_id/step_index = NULL) → SUCCESS
- 긴 메시지(600자) 저장 → 잘리지 않고 저장(len=600)
- 일정10 조회 → 2건, USER→ASSISTANT 시간순, intent(STEP_QUESTION) 보존
- 일정11 조회 → 1건만 (일정10 대화 안 섞임 = 격리 확인)
- 없는 일정(99) 조회 → 빈 배열 []
- GENERAL 조회 → 1건


8. 오류 테스트 결과 (거부 정상)
----------------------------------------------------------------------
- 잘못된 chatMode(WRONG) → ERROR 거부
- 잘못된 sender(ROBOT)   → ERROR 거부
- 빈 메시지("   ")       → ERROR 거부
- SCHEDULE인데 scheduleId 없음 → ERROR 거부

  ※ 자동 검증 스크립트로 완료기준 9개·테스트 9개 전 항목 통과 (PASS 17 / FAIL 0)
  ※ 회귀: 로그인·기존 일정 조회·/analyze 정상(HTTP 200) — 다른 기능 영향 없음
