[B] 대화 로그 DB 저장 기능 (신규 구현)
----------------------------------------------------------------------
구조 변화:
  Before) 대화 기록의 주인 = 클라이언트(앱 메모리).
          매 AI 요청마다 전체 히스토리(historyJson)를 통째로 업로드. 서버는 저장 안 함.
  After)  대화 기록의 주인 = 서버(DB).
          서버가 매 턴을 CHAT_LOG에 저장하고, 이전 대화도 DB 최근 N턴으로 재구성.
          클라는 "이번 발화 한 줄"만 전송.

신규 파일 3개:
  - server/src/main/java/com/nungil/domain/chat/ChatLogVO.java      (로그 1건 모델)
  - server/src/main/java/com/nungil/domain/chat/ChatLogMapper.java  (insert/최근N턴/일정별 조회)
  - server/src/main/resources/mappers/ChatLogMapper.xml            (SQL)

수정 파일 3개 (서버):
  - server/src/main/resources/schema.sql
        CHAT_LOG 테이블 + 인덱스 2개 추가
  - server/src/main/java/com/nungil/infrastructure/google/AnalysisOrchestrator.java
        매 턴 DB 저장 + 이전대화 DB에서 재구성 (자유 8턴 / 일정 6턴)
  - server/src/main/java/com/nungil/api/nungil/NungilAnalyzeController.java
        /analyze 에 userIdx·scheduleId 추가, /summarize 는 scheduleId 로 DB 조회

수정 파일 1개 (클라이언트):
  - client/app/src/main/java/com/example/myapplication/user/chat/UserChatActivity.kt
        conversationHistory 제거, historyJson 전송 제거,
        userIdx·scheduleId 전송, /summarize 는 scheduleId 전송

CHAT_LOG 테이블 구조:
  chat_id(PK, IDENTITY) | user_id | user_idx | schedule_id(nullable)
  | role('user'|'model') | kind('chat', 미래 'summary') | message | created_at
  - append-only(삭제/수정 없음), FK 없음(로그 유실 방지)
  - 인덱스: (user_id,user_idx,created_at), (schedule_id,created_at)
  - created_at 인덱스 = 향후 "어제/특정일" 날짜범위 회상 대비

컨텍스트 규칙:
  - 자유대화: schedule_id IS NULL 최근 8턴
  - 일정대화: 해당 schedule_id 최근 6턴
  - 자유대화 <-> 일정대화 완전 분리
  - 하위호환: userIdx 없으면 1, scheduleId 없으면 -1, 구 클라의 historyJson 무시/폴백

구현 중 잡은 버그:
  - MyBatis + Oracle null 함정: nullable 컬럼에 null 넣을 때 jdbcType 없으면
    "잘못된 열 유형" 예외로 조용히 실패 -> 자유대화만 저장 안 되던 것
    -> #{scheduleId,jdbcType=NUMERIC} 로 해결
